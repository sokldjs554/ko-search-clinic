## 1. 연구 질문과 Phase 0~1의 한계

회귀 게이트의 기각 능력은 별도로 측정해야 한다.

기존 **controlled-v1/dev 36질의(정상 20 / 실패 16)**의 선택적 규칙 복구는
**11/16**, 정상 최종 회귀 **0/20**, 탐지 **FP 9 / FN 2**이다. 이는 기존 개발셋
결과이며 이번 외부 데이터에서 재현한 수치가 아니다. Legacy Claude 16/16은
과거 자체 설계 평가셋 실험이다. 이 보고서의 Phase 2 결과와 합산하지 않는다.

기존 8문서·12작성질의·6개념군 파일럿은 저장소의 보고 기록을 확인했다.
**탐지 대상 2건에서 RulesPlus 유효 후보 0개**라는 부정적 기록을 보존한다.
그러나 원본 corpus/stimuli/qrels가 이번 체크아웃에는 없어 재실행·재검수를
완료하지 못했다. 기존 기록을 새 실행 결과로 표시하지 않는다.

## 3. 비교 조건과 실행 전 고정할 항목

비교 대상은 No Repair / RulesPlus / 실제 LLM이다. 기존 Phase 2의 공통
관측·근거·행동 스키마, 최대 3후보, 후보 봉인 후 평가 정답 개봉, 회귀 판정의
생성기 비공개 원칙은 유지한다. 기존 v1 프로토콜은 수정하지 않았다.

새 외부 데이터에는 별도 데이터·label commitment·source SHA·프롬프트·모델·
실패 정의·threshold·성공 기준·비용 상한을 고정한 실행 manifest가 필요하다.
현재 고정된 것은 **표본 선택 규칙과 원본 자료**이며, 실제 API 실행 프로토콜
전체를 고정·검증했다고 보고하지 않는다. 정상/실패 분류 기준은 점수를 보기
전에 정하고, 모든 후보를 봉인한 후 평가기에서 적용해야 한다.

현재 evaluator의 실제 유료 비교 차단 장치는 그대로 유지했다. 유료 API
transport와 승인된 실행 manifest를 연결한 최종 실행 경로는 아직 미완료다.
독립 데이터 검수가 통과하지 않은 상태에서 먼저 호출하는 방식으로 진행하지 않는다.

### 승인 전 비용 검토안 — 아직 승인되지 않음

제안 예산 USD 1.00과 14회는 아직 승인되지 않았다. 시험 호출도 하지 않았다.

## 5. 성공 사례 및 실패 사례

새 LLM 복구 성공·실패 사례는 없다. 이번의 확인 가능한 결과는 데이터
출처·hash 대조, 의미적 정답 충돌의 발견, 지속성 있는 비용 예약 테스트이다.
데이터의 판정 충돌을 LLM이나 RulesPlus의 실패 사례로 바꾸어 해석하지 않는다.

비용 안전장치는 예약을 SQLite에 기록한 뒤 호출하도록 사용할 수 있는
`DurableCallBudget`을 추가했다. 재시작 후 미결 호출·중복 질의·설정 변경·
상한 초과를 차단하고 오류 발생 시 예약을 유지한다. 이것은 호출 안전장치의
오프라인 검증이며 실제 공급자 API 통합 성공 증거는 아니다.

## 6. 예상과 달랐던 결과

외부 사람이 판정한 공개 자료라고 해도 이번 의미적 검색 복구 평가에 곧바로
쓸 수 있다고 판단하지 못했다. 명백한 답을 포함하는 음성 문단과 질문 범위가
다른 양성 문단이 있어, 모델 비교보다 라벨 재검수가 먼저라는 결론에 도달했다.
LLM에 유리하도록 질의를 바꾸거나, 문제 질의만 삭제한 결과는 만들지 않았다.

## 7. 일반화 범위와 남은 한계

현재는 독립 성능 결과가 없다. 작은 표본, 합친 후보 코퍼스, 미판정 쌍,
라벨 충돌, 의미·템플릿 중복 미확정, 공개 데이터의 사전학습 노출 가능성이
남아 있다. 그룹 신뢰구간을 계산하더라도 작은 표본의 한계를 없애지 않는다.
기존 프로토콜의 최소 20개 독립 검수 집단 요건도 이 12질의 표본만으로는
충족하지 못한다. LLM 우위·self-correction·autonomous agent·일반화를 주장하지 않는다.

실제 장애 요인은 (1) 기존 파일럿 원본 부재, (2) 새 자료의 의미적 판정 미확정,
(3) 공급자 키·모델 접근 미확인, (4) 새 데이터의 실행 manifest/API 연결 미완료,
(5) 별도 유료 승인 미취득이다. 원서 마감은 이 조건을 생략할 근거가 아니다.

## 9. 지원 서류에 사용할 수 있는 정확한 문장

현재 사용할 수 있는 것은 기존 검증된 개발셋 결과와 다음 수준의 과정 설명이다.

> 실제 LLM 비교를 위해 후보 생성과 평가 정답을 분리한 평가 구조를 준비하고,
> 외부 한국어 검색 데이터의 의미적 정답을 검토하고 있다. 검수 중 질문과
> relevance 판정 사이의 불일치 사례를 확인했으며, 최종 독립 평가와 실제
> LLM 성능 비교는 아직 완료하지 않았다.

실험 준비 코드와 테스트를 독립 성능 성과로 분류하지 않는다. 이번 외부 표본의
복구율·LLM 우위·일반화 성능에 관한 사용 가능한 성과 문장은 **없다**.
