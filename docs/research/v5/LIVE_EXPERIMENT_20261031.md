## 독립 평가와 아직 끝나지 않은 일

새 자료 후보는 [KLUE MRC v1.1](https://github.com/KLUE-benchmark/KLUE), 고정 revision `3efd98708a40ff49251fddde35453f8fbb11f536`에서 가져왔다. 200질의/300문서를 calibration40질의60문서, final160질의240문서로 분리하고 manifest/hash를 보존했다. **MRC 정답 문서 연결은 검색 관련성 정답의 대체물이 아니다.** 총40,800질의-문서 쌍의 검수표와 모호성/불일치 처리 지침을 준비했으나 사람 검수0건이다.

기존36질의·72문서와 접근 가능한 MIRACL213질의에 대한 정규화 exact 중복은0이었다. 의미상 유사 질의·개념 검수는 남았다. 과거120질의의 완전한 노출 목록과 v3/v4 원시 자료는 암호화돼 있고 권한 있는 복호화 키 경로를 아직 받지 못했다. 공개 수신자 키로는 복호화할 수 없다. 따라서 완전 노출 감사도 미완료이며 `final_evaluation_ready=false`를 유지한다. 기존 개발 데이터를 최종 독립 자료로 재사용하거나 KLUE proxy로 최종 우위를 계산하지 않았다.

- 독립 의미 검수: 후보15개, 판정자2인용 빈 양식, 불일치 adjudication 지침 준비. 사람이 수행한 판정은0건.
- 새 검색 관련성 검수: 데이터 관리자·독립2인 판정·불일치 조정자가 필요하다. 평가자는 생성/선택 출력에 정답을 주지 않는다.
- 새 GPT 후보 생성, 독립 최종 성능 비교, calibration, v3/v4 전체 탈락 원인 복원은 미완료다.
- 작은 기존 후보 풀은 과거 정답 gate에 의해 선별됐다. 문맥은 원래 생성 시점의 문맥이 아니라 질의·후보 표현으로 카탈로그에서 재구성했다. 2반복뿐이고 조건을 시간상 무작위 교차 배치하지 않았다. 이런 한계를 숨기지 않는다.

## 무료 재현·데모

[원격 증거 복호화 지침](REMOTE_EXECUTION.md)으로 승인 실행의 암호문을 새 `work/` 경로에 복구한다. 재현은 저장 응답만 사용하며 paid workflow를 재실행하지 않는다. 아래 예시는 기존 산출물을 덮어쓰지 않는 새 출력 경로다. `protocol.json`은 위 해시의 호출 전 프로토콜을 사용한다.

```bash
python scripts/compare_v5_conditions.py freeze \
  --bundle work/v5-live-41198330827/recovered/prepared/candidates.json \
  --candidate-source historical_scripted \
  --out work/my-replay/protocol.json
# 위 SHA256과 동일한지 확인한 후 진행합니다.
python scripts/compare_v5_conditions.py assemble \
  --bundle work/v5-live-41198330827/recovered/prepared/candidates.json \
  --protocol work/my-replay/protocol.json \
  --transport-dir work/v5-live-41198330827/recovered/run \
  --protected-root work/v5-live-41198330827/recovered/prepared/private \
  --out work/my-replay/assembly.json
python scripts/compare_v5_conditions.py score \
  --assembly work/my-replay/assembly.json \
  --labels work/v5-live-41198330827/recovered/prepared/private/labels.json \
  --out work/my-replay/private/report.json
python scripts/derive_v5_grounding.py --help
python scripts/analyze_v5_retrieval_aware.py --help
python scripts/export_v5_live_summary.py --help
python -m pytest -q -rs
clinic baseline
python -m searchclinic.api.explanation_api
```

`/demo/research.html`에서 실제9개 조건 집계와 비용·실패 원인을 본다. 로컬 상세 exporter 결과를 무시 목록의 `research-v5-live-details.json`에 두면36질의·6조건의 모델 판정, 원문, 인용 위치, 선택/보류 이유와 검색 전후가 표시된다. 공개 GitHub에는 상세 파일이 없으므로 공개 데모는 집계만 표시한다. 프론트엔드는 모델을 호출하지 않는다. 이전 저장 후보 재생과 RAG24 데모도 유지했다.

실제 저장 응답을 다시 적용해6개 의미 조건과 first_valid의 봉인된 application이 정확히 일치함을 확인했다. RulesPlus는 새 생성 실행의 메타데이터로 input hash가 달랐지만 순위·선택·후보별 결과는 같았다. 전체 assembly의 지연 값까지 byte-identical하다고 주장하지 않는다. 최신 전체 pytest/Ubuntu·Windows CI/baseline/브라우저 검증 결과는 [final-status.json](verification/final-status.json)에 기록한다. 테스트 통과는 연구 우위 입증이 아니다.
