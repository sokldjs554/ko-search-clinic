# 다음 평가 단계의 실제 작업량·표본 점검

상태: **규모 선택을 위한 분석이며 활성 프로토콜 변경이나 새 최종 실험이 아니다.** 기존51쌍과c조정6건을 보존했다. 현재 입력189질의·289문서, 동결된 split과 원문 연결을 사용해 두 축소안의 실제 ID 목록·해시를 만들었다. 새 검색 점수·최종 사람 정답·모델 응답을 보고 표본을 고르지 않았다.

## 검수자 한 명 기준의 전체 예상 항목

두 사람이 각각 수행하는 양이다. 시간은 실측 처리 속도가 아니라 비교를 위한 가정이며 긴 문서·개념 중복 검토·불일치 조정·방법 보정·실험 분석 시간은 포함하지 않는다. 후보는 질의당 최대2개를 가정했으며 그 수를 바꾸면 의미 검수와 호출 수를 다시 계산해야 한다. 기존51쌍은 보정·오류분석 기록으로 유지하고 새 최종 결과에 재사용하지 않는다.

32안은16안보다 표본 변동을 줄일 여지가 있으나 검수 시간이 늘어난다. 하루 수준의 검수만 가능하면16안은 소규모 탐색 비교로 한정하는 것이 현실적이다. 두 안 모두 문서 코퍼스도 줄이므로 원래233문서 검색과 다른 과제가 된다. 작은 코퍼스에서의 효과를 원래 전체 자료나 일반 한국어 검색으로 확대하지 않는다. 이 선택은 아직 확정되지 않았으며 새 대량 검수 파일을 배포하지 않았다.

## 실제 선택·연결 검사

고정 seed `ko-search-clinic-v5-feasibility-20261102-v1`와SHA256 ID 순서로 각 split 안에서 질의와 추가 문서를 선택했다. 질의의 원래 연결 문서는 모두 유지했다. 이미 반복 검토한 질문의 개념군은 제외하고 개발/최종의 문서·개념군 연결을 검사했다. 두 안 모두 알려진 그룹 기준 split 교집합0이며 source linkage가 완전하다. 이 검사는 의미적으로 같은 개념의 별도 ID나 알 수 없는v4노출까지 증명하지 않는다.

원본 source의 답 가능 여부 메타데이터를 사후 집계해 분포를 확인했으며 이 집계로 다시 뽑지 않았다. 보정8질의는 원본 답 가능5·답 없음3이다. 최종16안은11·5,32안은25·7이다. 원본MRC답 가능 여부는 검색 관련성 정답이 아니다. 답 없음이 전체 코퍼스에서도 확인되는 질의의 처리 규칙은 최종 결과 전에 고정해야 하며, 유리한 점수가 나오도록 교체하거나 제외하지 않는다. 최종 점수에 들어갈 유효 질의 수는 이 단계의16/32와 달라질 수 있으므로 현재 수를 확증 표본 수로 보장하지 않는다.

전체ID와 원문은 비공개 탐색 파일에만 있다. [집계·해시](verification/evaluation-feasibility-20261102.json)는 공개 가능 항목만 포함한다. 후보 파일은 제안 미리보기이지 현재 프로토콜에 활성화된 데이터가 아니다. 원래 자료와 프로토콜은 바꾸지 않았다.

## 통계적으로 입증 가능한 범위

현재 실제 코드 `comparison.PRIMARY`는Rubric을 주조건으로 하고 No Repair·RulesPlus 각각의97.5%양측 신뢰구간 하한이+0.01 이상이며 정상 회귀가0일 때만 수치상 성공으로 판정한다. 각 질의 내 반복을 평균한 뒤 개념군 bootstrap2000회, random100회, 고정 seed를 사용한다. 실제 final회귀 기준은 주조건 어느 반복이든 정상 질의의 어느 지표든1e-12초과 감소0건이다. 과거 개발 진단의0.02회귀 기준과 섞지 않는다.

기존36질의 개발 결과를 다시 읽어 대응 차이의 표준편차를 계산했다. Pair−RulesPlus는0.233243, Rubric−RulesPlus는0.455854다. 정상근사·독립 동일 크기 그룹·한 비교에서80%검정력이라는 단순 가정으로+0.01 하한을 넘기려면 다음 정도의 실제 평균 차이가 필요하다.

|---|---:|---:|
| 16 | 약+0.190 | 약+0.361 |

이는 새 자료의 검정력 보장이 아니다. 두 비교 동시 성공·정상 회귀0조건·그룹 의존성·유효 표본 감소를 포함하면 더 어렵다. 전체코퍼스와 작은코퍼스의 분산도 같지 않다. 따라서16/32안에서 작은 효과의 확증 우위를 약속하지 않으며, 점수·대응 차이·구간과 실패 원인을 그대로 보고해야 한다. 모델confidence0.8을 보정된 개선 확률이나 최적 임계값으로 취급하지 않는다.

## 호출 수와 기존 구현의 조건

질의당 새 후보 생성1회, 후보 최대2개, Pair/Context/Rubric 각2회라면 총 호출 상한은13×질의 수다. 새 보정까지 합쳐16안은최대312회,32안은520회이며 기존 전수 범위는2,457회다. 이는 구현·후보 수에 대한 가정으로 계산한 호출 계획이며 비용 승인 요청이나 실제 실행이 아니다. 새 모델의 접근 가능 여부·공식 단가·입출력 토큰 상한·총비용은 실행 직전에 다시 검증해 별도 승인받는다. 기존90회 승인은 이미 소비됐고 이번 모델 호출은0회다.

현재finalgate는 사람 관련성·후보 의미 판정,질의 적격성,개념 독립성,역사 노출 감사,후보 생성 증거,프로토콜 선고정을 모두 요구한다. 성공v4실행의 노출 감사가 미완료여서 규모만 줄여도 이gate가 통과되지는 않는다. 해당 값을 true로 꾸미거나gate를 완화하지 않았다. 노출 한계를 남긴 기술적 비교는 독립 확증 평가와 구분해야 하며 명칭만final로 바꿔 해결하지 않는다.

문서의 과거 ‘최소효과·안전성 합의 전’ 문구와 코드의 실제 고정값이 다르므로, 새 프로토콜은 선택한 방법·임계값·안전성·무관련질의 처리·통계·예산을 명시하고 구현과 함께 다시 고정해야 한다. 원래Rubric 전체보류 실패와 사후 개발 규칙을 섞거나 새 최종 자료에서 주방법을 선택하지 않는다.

## 다른 공개 정답 자료의 검토

이미 조사한MIRACL train/dev는 과거 노출 때문에 새독립 경로로 채택하지 않는다. [Mr.TyDi](https://ir-datasets.com/mr-tydi.html)는 얕은 사람 주석에서 얻은 희소 관련성 자료이며, [mMARCO](https://github.com/unicamp-dl/mMARCO)는 기계 번역된MS MARCO다. 자료명만 바꾸면 전수 판정·번역 타당성·노출 문제가 해결된다고 주장하지 않는다. 미판정 문서를 사람이 무관하다고 판정한0으로 바꾸지 않았고 새공개자료를이번최종평가로채택하지 않았다.

## 후속 결정: 추가 검수 확대 보류

검수자 한 명당 하루(4~8시간) 가능하다는 답을 받았다. 이후 사용자가 추가 검수 없이 현재 자료로 LLM 비교 실험을 진행하도록 요청했다. 따라서 이 문서의 16/32질의 대안은 채택하지 않았고 새 검수 파일도 배포하지 않는다. 기존 36질의 개발셋에서 새 GPT 후보를 생성해 비교하는 [후속 실행 계획](DEVELOPMENT_LLM_CLOSEOUT_PLAN_20261102.md)으로 전환했다. 이는 새 독립 평가의 완료나 최종 우위 인증이 아니다. 기존 51쌍 판정과 모든 제출 이력은 보존한다.
