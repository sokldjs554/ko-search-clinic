## 연구 문제와 제안 방법

한국어 검색을 고치는 LLM 후보에는 형식은 맞지만 질문 대상·의미 범위를 바꾸는 수정이 섞일 수 있다. 기존 검색 수정 후보에 Pair(표현 쌍), Context(질문과 검색 문맥), Rubric(문맥과 의미 기준)을 적용하고, 의미·근거 조건을 통과한 후보를 선택한다. 마지막에 봉인된 검색 결과만 별도 정답으로 채점한다. 모델 confidence는 검색 개선 확률이 아니며 0.8은 보정·최적화된 임계값이 아니다.

후보 생성 성능과 선택 성능을 구별했다. 실제 의미 판정은 기존 scripted 15후보/14질의를 대상으로 했고, 전체 검색 채점은 기존 개발 36질의(정상20/실패16)다. RulesPlus는 다른 생성기의 14후보/13질의이므로 전체 경로 비교다. 저장 후보를 GPT 기본 생성 결과라고 부르지 않는다. 과거36·120질의를 독립 평가로 재사용하지 않았다.

## 실제 사람 판정 수령과 조정

사용자가 서로 다른 실제 사람으로 확인한 a·b의 CSV 각15행을 수령했다. c는 조정자로 배정됐다. 원본 두 차례 제출, 시간 변환본, 사용자 설명, 정규화 변경 내역을 비공개로 보존했다. `fasle`는 `FALSE`의 오타이며 **출력이 잘못됐다는 판정**이다. 이를 단순한 표현 분리로 축소 해석했던 어시스턴트의 해석은 철회했다. 안내 혼선과 반복 확인은 연구 수행 과정의 한계로 기록하며 판정자 탓으로 돌리지 않는다.
