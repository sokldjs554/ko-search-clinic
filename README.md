# ko-search-clinic

한국어 검색 수정 후보를 **생성 → 형식 검사 → 의미 검증 → 선택·보류 → 검색 적용 → 별도 채점**하는 연구 프로젝트입니다. 연구 질문은 “LLM이 만든 수정 후보 중 의미를 보존하고 실제 검색을 개선하는 후보를 어떻게 고를 것인가?”입니다.

**2026-10-31 실제 LLM 90회 판정을 완료했습니다. RulesPlus 대비 성능 우위는 입증하지 못했습니다.** 기존36질의·저장 scripted 후보15개의 개발 실험이며 새 GPT 후보 생성이나 독립 최종 평가 결과가 아닙니다. v3·v4 결과는 보존했습니다.

## 제안 방법과 실제 비교

같은 후보를 **Pair(표현 쌍), Context(질문·검색 문맥), Rubric(명시적 판단 기준)**으로 각각2회 판단했습니다. 동의 관계, 같은 대상, 의미 범위, 인용 원문을 검사하고 후보별 검색을 원래 엔진에서 독립 적용합니다. 최종 정답은 순위 봉인 후 별도 채점 프로세스에서만 읽습니다. 모델 confidence는 보정된 검색 개선 확률로 취급하지 않습니다.

| RulesPlus 생성 + 첫 유효 처방 | 0.859490 | 13 | 1 |

주조건 Rubric은 전체 보류로 개선에 실패했습니다. Pair의 RulesPlus 대비 차이는−0.053326, 탐색95%구간[−0.140994,+0.004117]입니다. 정상 악화0건만으로 안전성이나 우위를 입증하지 않습니다. 같은 적용 수의 Matched Random100회, Recall@10/P@5, 실패 개선·유용 후보 보류·반복 변동·대응 구간은 [전체 보고서](docs/research/v5/LIVE_EXPERIMENT_20261031.md)에 있습니다.

모델은 `gpt-4.1-mini-2025-04-14`, 완료90/90·API 오류0, 입력83,748/출력15,315토큰, 사용량 기준 비용 추정 **$0.0580032**(승인 상한$0.72, 실제 청구액 미확인)입니다. 원시 응답은 암호화 보존했고 상세 질의·정답·원문은 공개하지 않았습니다.

코드 검증: 로컬 및 [Ubuntu·Windows CI](https://github.com/sokldjs554/ko-search-clinic/actions/runs/41201460882) 각각 **671개 통과·2개 선택 의존성 제외**, 검색 baseline 유지, 공개/로컬 데모 브라우저 검사 완료입니다. CI 통과와 연구 우위는 별개입니다.

## 개선·실패 사례와 새로운 발견

- **인용문 존재와 위치 정확성은 달랐습니다.** Context/Rubric 인용81개 중79개는 원문에 있었지만 정확한 좌표는6개였습니다. 전면 보류에는 의미 판단 외에 좌표 생성·검증 병목이 있었습니다.
- **의미 confidence는 검색 효용을 잘 정렬하지 못했습니다.** 한 질의에서 높은 confidence의 후보는 결과0건, 낮은 후보는2건을 만들었지만 두 반복 모두 전자를 선택했습니다.
- **추가 호출 없는 사후 개발 규칙을 분리 평가했습니다.** 원문에 유일하게 존재하는 인용의 위치만 복원하면 Rubric 평균은0.639498이었습니다. 원래 검색이0건일 때 의미 기준을 통과하고 결과를 만든 후보를 우선하면 Pair는 두 반복 모두0.833943으로 높아졌습니다. 정상 악화0건이지만 RulesPlus보다 낮고 독립 검증 전입니다. 원래 실험을 이 결과로 대체하지 않았습니다.

## 연구의 한계와 다음 조건

새 KLUE MRC 자료 후보200질의·300문서를 확보하고 분할·해시·중복 검사·검수표를 준비했습니다. MRC 정답 연결은 검색 관련성 정답이 아니며 **사람 검수0건**, 의미 중복·과거120질의 전체 노출 감사도 미완료입니다. 기존 개발 점수로 최종 독립 우위를 주장하지 않습니다. [검수 지침](docs/research/v5/HUMAN_REVIEW.md).

v3·v4 암호화 원시 자료의 권한 있는 복호화 경로는 아직 없어73→63→2 전체 탈락 원인을 복원하지 못했습니다. 기존 유용 후보11개가 gate를 통과한 사실을 유지하며 근거 없이 과도한 보수성을 원인으로 단정하지 않습니다. [감사 기록](docs/research/v5/AUDIT.md).

재현은 아래 **실행과 재현**, 실제 저장 응답의 무료 재분석은 [실험 보고서의 명령](docs/research/v5/LIVE_EXPERIMENT_20261031.md#무료-재현데모)을 따릅니다. API 재호출·독립 평가·main 병합은 완료하지 않았습니다.

## 추가 연구: 저장 후보의 개발 진단

기존 상품 카탈로그 72건 · 평가셋 36질의(건강 20 + 실패 16), PR #1에 실제 제출·저장된 고유 후보 15개를 **현재 고정 엔진에 하나씩** 다시 적용했습니다. 과거 진단·정답 게이트로 이미 선별된 부분집합입니다. 새로운 독립 데이터, GPT 비교, 새 의미 선택기의 성능은 아닙니다.

| 조건 | 전체 nDCG@10 | 실패 nDCG@10 | Recall@10 | Precision@5 | 실패 개선 | 정상 회귀 |
|---|---:|---:|---:|---:|---:|---:|
| No Repair | 0.583943 | 0.069572 | 0.597222 | 0.200000 | 0/16 | 0/20 |
| 저장된 첫 후보 적용 | 0.849239 | 0.694572 | 0.875000 | 0.316667 | 10/16 | 2/20 |
| 관측 후보 Oracle + 수정 없음 | 0.889498 | 0.757072 | 0.902778 | 0.327778 | 11/16 | 0/20 |

Oracle은 정답을 이용한 **진단 상한**이며 운영 정책이 아닙니다. 첫 후보의 평균 차이는 +0.265296, 22개 정답 문서 중첩군의 사후 bootstrap 95% 구간은 [0.125204, 0.379586]입니다. 이 구간은 편향된 개발 자료의 기술 통계이며 독립 일반화의 근거가 아닙니다. 적용 수를 맞춘 무작위 100회에서는 14개 가용 질의에 모두 적용하므로 두 후보가 있는 한 질의의 선택만 변합니다.

유용한 저장 후보 11개는 기존·수정 게이트 모두 채택했습니다. 이 부분집합에서는 게이트의 유용 후보 과잉 기각이 관측되지 않았습니다. 질의별 JSON·CSV는 아래 무료 재현 명령으로 로컬에서 생성합니다. 상세 데이터의 GitHub 공개는 별도 승인 전까지 보류합니다. 이 과거 후보 재생 단계의 API 호출·새 토큰·API 비용은0입니다. 위 실제90회 의미 판정과 별도입니다. v5 지표는 전체 정밀도, 양의 관련성, 고정 분모 5의 Precision@5를 사용하며 과거 지표 구현과 섞지 않습니다.

## 실행과 재현

Python 3.11 또는 3.12. Windows에서는 `.venv\Scripts\Activate.ps1`을 사용합니다.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -c requirements/ci-py311-312.txt -e '.[api,mcp,dev]'
python -m pytest -q -rs
clinic baseline
python scripts/replay_saved_development.py --out work/development-replay.json --csv work/development-funnel.csv
python scripts/prepare_v5_development.py --out work/v5-prepared
python -m searchclinic.research_v5 --help
```

후보 준비는 무료이며 실제 모델 응답을 만들지 않습니다. 요청 파일, 빈 판정 파일과 채점 전용 정답 파일을 분리합니다. [봉인·적용·채점 명령](docs/research/v5/PROTOCOL.md)을 따르세요. 기존 연구 CLI와 `clinic heal --engine rules+`는 유지되지만, 정답표로 채택하는 개발 진료 경로입니다.

Kiwi **0.24.1 + 모델 0.24.0 + `cong-global`**을 PR #2에서 재사용했습니다. `포도` 분석 회귀를 해결했고 기존 `docs/BASELINE.json`은 바꾸지 않았습니다. CI의 전체 의존성 제약은 `requirements/ci-py311-312.txt`, 과거 연구 환경은 `docs/research/constraints.txt`에 별도 보존합니다.

회귀 게이트의 표적 최소 이득 0.05와 질의별 허용치 0.02는 유지했습니다. 전체 평균 허용치는 이전 0.02에서 수치 오차 1e-12로 분리하고, 이미 반올림된 보고 평균으로 판정하지 않습니다. 과거 방식은 `run_gate(..., mean_epsilon=0.02)`로 명시할 수 있습니다. 과거 결과를 새 정책의 결과로 바꾸지 않았습니다.

- `http://127.0.0.1:8000/demo/research.html`: 실제90회 의미 판정의 집계·비용·실패 원인과 사후 개발 분석. 로컬 exporter의 `demo-details.json`을 무시 목록의 `src/searchclinic/web/research-v5-live-details.json`에 두면 질의별 실제 판정·인용·선택·검색 전후가 표시됩니다. 기존 저장 후보 재생도 별도로 유지합니다.

RAG24는 별도 모델·과제의 사후 인용 검증입니다. 지원 6·보류 12·차단 6, 후보 채택 4·기각 2는 [기존 기록](docs/verification/alba-20261027/README.md)입니다. 검색 성능 우위와 합산하지 않습니다. 기본 서버에서 유료 생성은 비활성화됩니다.

## 아직 확인하지 못한 것

- v3·v4 암호화 원시 결과의 질의별 퍼널·전체 후보 Oracle: 복호화 자료 없음.
- 실제90회 판단의 독립 의미 정오 검수: 아직0건. 모델 출력 빈도와 검색 효용을 의미 정확도로 대체하지 않음.
- 새 최종 평가: KLUE200질의·300문서 후보 확보, 독립 관련성·개념 검수와 완전 노출 감사 미완료. 기존 120질의를 새 맹검 자료로 재사용하지 않음.
- 새 방법 대 RulesPlus·GPT의 독립 성능: 미측정. 기존 후보 선택기의 개발 성능·지연·비용·2회 반복은 위 실험에 기록.
- RFL 학습: 검수된 충분한 후보 판정 자료가 없어 수행하지 않음. [논문 검토와 후속 실험 조건](docs/research/v5/PROTOCOL.md).

면접에서는 실제90회 통제 실험, 인용 좌표 병목과 confidence/검색 효용 불일치 발견, 정답 없는 선택 규칙의 개발 개선을 설명할 수 있습니다. RulesPlus 우위와 독립 검증은 달성했다고 말할 수 없습니다.
